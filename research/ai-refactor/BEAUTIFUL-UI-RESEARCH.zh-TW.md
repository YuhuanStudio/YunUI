**研究日期：2026-10-01。** 本文件供下一階段設計審查使用，沒有移植程式碼，也沒有提出已獲批准的成品視覺稿。Beautiful UI 官網列出 21 個 AI 介面範例；對照時以官網、其連結的 GitHub 原始碼固定版本 `44a274e598395ab61e7c96c26fda2758780253b7` 為證據。逐項來源、授權與 YunUI 本地檔案見[參考清單](./BEAUTIFUL-UI-REFERENCES.json)。[官網](https://www.beautifului.dev/) · [原始碼 README](https://github.com/slev12397/beautiful-ui/blob/44a274e598395ab61e7c96c26fda2758780253b7/README.md) · [MIT 授權](https://github.com/slev12397/beautiful-ui/blob/44a274e598395ab61e7c96c26fda2758780253b7/LICENSE)

## 可確認的參考背景

上游 README 將 Beautiful UI 描述為 React 元件與設計 token 基礎，並把 `/harness` 說明為串接假情境的示範殼；它列出的替換點是把本機示範資料接到真實 agent 事件。因此，畫面可以證明互動設計存在，卻不能證明持久化、網路 API 或正式執行生命週期。[上游 README](https://github.com/slev12397/beautiful-ui/blob/44a274e598395ab61e7c96c26fda2758780253b7/README.md#-wiring-the-harness-to-a-real-agent)

上游採用 Next.js、React、Tailwind CSS v4 與 TypeScript；發佈方式以 shadcn registry／複製元件為主，並列出元件的內部與 npm 相依。Repo 及官網授權聲明為 MIT；README 另指出 `SidebarNav` 使用需授權的 `@central-icons-react` 圖示套件，不能把整個 repo 的 MIT 狀態誤解成該商用圖示也可任意複製。[README](https://github.com/slev12397/beautiful-ui/blob/44a274e598395ab61e7c96c26fda2758780253b7/README.md) · [package.json](https://github.com/slev12397/beautiful-ui/blob/44a274e598395ab61e7c96c26fda2758780253b7/package.json) · [LICENSE](https://github.com/slev12397/beautiful-ui/blob/44a274e598395ab61e7c96c26fda2758780253b7/LICENSE)

官網及 repo 對應的 21 個範例如下。表中「上游行為」取自公開 gallery 和固定 commit 原始碼；「YunUI 對照」是依目前本地 API 作的能力比較，不代表設計已批准。

## YunUI 的現有基礎與設計邊界

YunUI 已有一組可組合的 agent process API：[AgentRunStatus](../../src/ai/agent-run-status.tsx) 負責單一持續更新的當前狀態；[AgentTimeline](../../src/ai/agent-timeline.tsx) 將 reasoning、tool running/done/error 與 approval 事件呈為歷程；[ThinkingBlock](../../src/ai/thinking-block.tsx) 是獨立推理 disclosure。Chat 是 slot/controlled 元件；Markdown 和程式碼使用 content entry。這些 API 已明確分開「目前狀態」和「已發生歷程」，建議作為導入新型態的契約基礎，而不是把 gallery 的計時假資料帶進元件。[AI exports](../../src/ai/index.ts) · [Chat exports](../../src/chat/index.ts) · [Content exports](../../src/content/index.ts)

Beautiful UI README 明述自己的藍調中性、Inter/JetBrains Mono、緊密圓角、分層陰影及 motion token；這些是上游設計語言。此次要學習的是狀態拆分、資訊層級、分組/展開/確認的互動語意，不應複製上游 CSS、色值、圓角、陰影、字體、圖示或動畫。成品仍應使用 YunUI 的既有 token、圓角、陰影、字體與圖示/Motion 慣例；每一份視覺和互動提案先給使用者確認，再進入正式實作。[上游設計系統說明](https://github.com/slev12397/beautiful-ui/blob/44a274e598395ab61e7c96c26fda2758780253b7/README.md#-the-design-system) · [上游 globals.css](https://github.com/slev12397/beautiful-ui/blob/44a274e598395ab61e7c96c26fda2758780253b7/app/globals.css)

## 建議的分階段審批單位

以下是研究後的建議審批切片，**不是實作授權**。每一切片先交付獨立視覺稿與互動狀態清單，收到使用者明確批准後，才實作該切片。

1. **Composer + Chat**：空白/輸入中/送出中/停止生成狀態，快捷鍵、工具列/附件槽、對話訊息、上下文切換；先決定 @ mention、`/` command、model picker、dictation 是 YunUI API 還是消費端 slots。
2. **Agent process**：`AgentRunStatus` 的 live phase、`AgentTimeline` 的 reasoning/tool/task/approval 排列、折疊與預設開啟、成功/失敗/等待、長輸出與小螢幕閱讀。此單位再分 thinking disclosure、tool output/diff disclosure、task rows、approval actions 四張互動稿逐項核准。
3. **需要額外產品語意才排期的項目**：推薦決策、retrieval/context chunks、記錄表格/可審核 diff、選取文字 action bar、流程圖編輯、Insight page、遠端 Agent Screen。先由使用者選中要做的項目，再各自提案，不因上游有範例就全數加入 YunUI。

## 確認事實與推論界線

- **已確認**：官網有以上 21 個 gallery section；repo commit、package stack、MIT 授權、設計 token 說明和元件 props/state/callbacks 由固定 commit 原始碼可查。官網有受控互動範例，但 repo README 說 harness 是假情境示範。[官網](https://www.beautifului.dev/) · [repo README](https://github.com/slev12397/beautiful-ui/blob/44a274e598395ab61e7c96c26fda2758780253b7/README.md)
- **已確認的發布細節**：上游 README 指出 SidebarNav 的 `@central-icons-react` 是商用授權圖示依賴；shadcn 公開 registry 可下載清單在本次 audit 未列 Agent Screen，雖然 repo 有該原始碼。這不影響 MIT 授權對其餘原始碼的聲明，但不應假設每個 demo 都有同等複製/安裝路徑。
- **推論／建議**：哪些 interaction 更適合 Yunxin/其他消費端、是否新增 props、視覺表現和 API 封裝都要由實際產品需求及使用者審批決定。研究結果不構成全量實作清單。
