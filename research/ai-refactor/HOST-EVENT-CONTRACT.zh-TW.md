# AI 移植的宿主事件邊界（準備稿）

狀態：準備中，未定為公開 API；不代表視覺/交互批准。

來源基準：Beautiful UI `44a274e598395ab61e7c96c26fda2758780253b7`，
`components/primitives/{PromptBar,ChatComposer,ThinkingState,TaskRows,ToolChips,ApprovalCard}.tsx`。

## 原始碼中需要分離的展示行為

- `ChatComposer` 在送出後用 500/1400/1200ms 計時器推動回覆階段；移植後不能以時間推斷後端成功。
- `ThinkingState`、`TaskRows`、`ToolChips` 用本地計時器推動階段或工具結果；正式元件應顯示宿主傳入事件。
- `PromptBar` 只有 `onSend(text)` 不能完整傳達來源、模型和附件；這些值必須成為可追蹤的宿主輸入。
- `ApprovalCard.onSubmitted` 表達問卷答案，不等於執行工具的授權；問答與有副作用的操作批准需區分。
- 裝飾動效、展開收合和問卷過場計時可以留在呈現層；它們不能改變執行結果。

## 正式 API 實作前必須覆蓋的案例

| 情況 | 宿主責任 | 元件應呈現的資訊 |
| --- | --- | --- |
| 送出 | 接收文字、穩定的模型/來源/附件 ID，建立 run ID，回報接受或拒絕 | 送出等待、拒絕原因，保留未接受的草稿 |
| 串流 | 提供事件 ID、run ID 與順序，去重並處理舊 run 事件 | 已確認收到的部分內容，不能虛構完成 |
| 工具 | 傳入穩定工具呼叫 ID、狀態、展示參數與允許展示的輸出 | 執行中、完成、失敗與可展開詳情 |
| 批准 | 提供批准請求 ID、操作內容、是否仍有效；確認後由宿主執行 | 待確認、提交中、接受/拒絕/已失效；不可點擊即宣稱成功 |
| 取消 | 接收特定 run 取消請求，確認終止或拒絕 | 取消中與已取消，保留已有輸出 |
| 失敗/逾時 | 提供可替換錯誤文字與重試能力，不把模型異常當空成功 | 失敗狀態、部分結果、宿主允許的重試入口 |
| 來源權限 | 決定可用來源/附件與錯誤；不得由 UI 宣稱已連接 | 可用、載入中、拒絕與失效 |

展示層可以維護選單開關、游標、展開內容、草稿和焦點。模型請求、工具執行、授權判斷及可信執行日誌仍由宿主負責。研究草稿只使用明確的本地 fixtures，沒有真正執行後端。

接下來將這些案例對照 D3 的具體交互，取得擁有者審核後才定公開 API 與正式實作；不能把本文件視為已完成後端整合。
