import { Navbar } from "yunui/ai";

懸浮式頂部導覽列：包含圖示、帶捲動監聽與作用中連結樣式的置中連結、主題/語言控制項插槽，以及內建行動端選單的驗證按鈕。連結為純資料（`NavLink[]`），導覽透過設定的 `Link` 配接器進行。它自行管理行動端選單狀態。

## 匯入

```tsx
import { Navbar } from "@yuhuanowo/yunui/ai";
```

## 基礎用法

導覽列固定在視窗頂部。提供 `links` 與 `appName`；宿主透過配接器提供路由。

## 插槽

這個導覽列是為「不只有 logo 與連結」的宿主設計的。每個插槽都是可選的，不傳就跟原本一樣。

| 插槽 | 落點 |
| --- | --- |
| `brand` | 取代首頁連結內的 logo ＋字標——可傳只有圖示的 logo 或自訂組合。 |
| `actions` | 右側群組中、語言／主題藥丸之前的額外控制項。與該群組其餘部分一樣僅桌機顯示。 |
| `languageSwitcher` / `themeToggle` | 兩個標準藥丸。 |
| `account` | 已登入時的控制項；在桌機與行動裝置都會取代登入／註冊那一組。 |
| `mobileMenuHeader` | 行動選單頂部，連結之上。 |
| `mobileMenuFooter` | 行動選單底部。會**取代**該處自動出現的語言列，讓你自己排版那一行。 |
| `label` | `<nav>` 地標的無障礙名稱——頁面上有多個 nav 時必須給。 |

這些插槽之所以存在，是因為有兩個應用寧可 fork 這個元件也不用它：YunUI 自己的站台需要只有圖示的品牌與一個 GitHub 連結，YunNEWS 需要一個搜尋按鈕。兩者都無法表達，於是各自複製了一份。那是 API 的設計失敗，不是消費端的問題——插槽就是修正。
