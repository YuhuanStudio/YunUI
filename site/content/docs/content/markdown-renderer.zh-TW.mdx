完整的內容渲染器。給它一段 markdown 字串，它就會渲染 GitHub 風格 markdown（表格、任務清單、刪除線）、KaTeX 數學（行內 `$…$` 與區塊 `$$…$$`）、Shiki 高亮的圍欄程式碼區塊、` ```mermaid ` 圖表、GitHub 風格 `> [!NOTE]` 提示框、標題錨點，以及惰性、可縮放的圖片——全都在一個元件裡。用 `urlTransform` 改寫圖片/連結 URL，用 `onCodeEdit` 在程式碼區塊上顯示「編輯」按鈕。

## 匯入

```tsx
import { MarkdownRenderer } from "@yuhuanowo/yunui/content";
```

需要主端應用引入 `@yuhuanowo/yunui/content.css` 與 `katex/dist/katex.min.css`，並安裝內容對等相依（見[內容概覽](/docs/content)）。

## 用法

```tsx
<MarkdownRenderer
  content={message.content}
  urlTransform={(url) => (url.startsWith("/") ? `${API_HOST}${url}` : url)}
  onCodeEdit={({ code, language, filename }) => openInEditor({ code, language, filename })}
/>
```

Markdown 輸入中的原始 HTML 會在標題 ID 產生後、KaTeX 數學公式渲染前進行清理。常見格式以及 GFM 表格、任務清單核取方塊、提示框和程式碼高亮等支援的 Markdown 功能會保留。危險或不支援的原始 HTML 會被清除，包括指令碼、iframe、嵌入物件、內嵌事件處理器和內嵌樣式等不安全屬性。這是渲染器的輸入清理措施，不代表任意內容都絕對安全。

`urlTransform` 可改寫圖片和連結 URL，但改寫後的結果仍會經過 React Markdown 的安全協定過濾。相對 URL 以及 `http:`、`https:`、`mailto:`、`irc:`、`ircs:` 和 `xmpp:` 等支援的協定會保留；`javascript:`、`data:` 等不安全協定會被拒絕。

清理後的 ID 會加上 `user-content-` 前綴以避免 DOM clobbering；相符的本地片段連結也會同步調整，仍可跳轉至對應 ID。

`linkOrigin` 可選提供穩定的網站 origin，讓 SSR 與瀏覽器使用相同規則判斷連結。同源絕對連結視為站內連結，其他絕對連結視為外連。不傳 `linkOrigin` 時，絕對 HTTP(S) 與協定相對 URL 視為外連，相對連結和片段連結視為站內連結。

```tsx
<MarkdownRenderer content={markdown} linkOrigin="https://example.com" />
```
